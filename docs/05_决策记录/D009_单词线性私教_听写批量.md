# D009｜学习流程架构：单词线性私教 + 听写批量

- 日期：2026-09-11
- 议题：1 词走 8 步 vs 步骤批量 vs 单词私教
- 背景与冲突点：
  - 原 v0.3 流程：1 词走完 8 步（听音→跟读→分段→归位→找特位→合成→主动回忆→听写）。
  - D009 初稿曾提议"步骤批量"（5 词一起听音、5 词一起听写）模拟大班教学。
  - 用户 2026-09-11 明确纠正：**本产品是"一对一私教"场景，不是大班**。一对一就应该 1 词学透，再下 1 词。
  - 大班才需要"听 5 词一起→抽查 1 人"；私教是"这词你真会了吗？不到位不下一个"。
  - 听写环节的"批量"是合理的——5 词一起朗读、学生作业本写，效率高。
- 各角色观点摘要：
  - 产品负责人：**单词线性**。一对一场景 = 单词精做。
  - 资深英语教师：**单词线性**。私教定制 = "不到位不下一个词"。
  - 学习科学专家：单词线性 = 深度编码（Craik & Lockhart 1972 加工层次模型）。每词走完 8 步 = 多重加工形成强记忆。
  - 初一学生代表：单词线性不切来切去，专注。
  - 家长代表：每词 8 步做透 = 踏实。
  - UI 设计师：单词线性 = 单卡片，UI 简洁。
  - 技术负责人：现状 8 步函数签名 `(word)` 已是单词粒度，无需重构。
- 最终决策：
  - **单词线性（1 词走完 8+1 步）**：保留现状模型，每词走完才下一个
  - **听写环节改为批量**（D011 范围）：N 词一起 TTS 朗读 + 学生作业本写 + 拍照上传（D011 v0.5）
  - **新增第 8 步"听写前跟读"**（D012）：听写前 TTS 慢速 + 学生跟读 1 次，把"音→嘴"和"音→手"绑死
- 决策人/讨论来源：用户 2026-09-11 私教场景洞察 + 7 角色评审
- 备选方案与放弃原因：
  - 放弃「步骤批量听音 5 词」：私教场景无意义，反而打断学生专注。
  - 放弃「步骤批量跟读 5 词」：跟读必须单词粒度才有针对性。
  - 放弃「听写前不做跟读」：听写前跟读是"音→口→手"的关键桥梁，缺了学生听写时嘴不动手，效率低。
- 决策后的影响：
  - `app.js` `renderCard`：保持单词粒度不变；新增"听写前跟读"步骤
  - 听写页（`renderDictation`）：从"单词 TTS"改为"N 词 TTS 批量朗读"（D011 实现）
  - 听写流程：5 词一起听→作业本写→拍照→批改（v0.5）
- 验收标准（v0.4.x）：
  1. 单词学习：1 词走完 8 步 + 第 8 步听写前跟读 → 自动进入下 1 词
  2. 5 词全部学完后，弹出"准备听写 N 词"统一听写页
  3. 复习词走"快速通道"（仅 3 步：听音→主动回忆→听写）
- 版本：v0.4.x（D009 覆盖 D009 初稿"步骤批量"部分）
