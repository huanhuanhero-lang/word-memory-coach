# D003｜数据存储策略：分层存储，v0.1 不上数据库（2026-09-11 修订）

- 日期：2026-09-10 首次；2026-09-11 修订
- 议题：是否在 MVP v0.1 引入数据库存储单词信息和用户信息
- 修订背景：
  - 用户 2026-09-11 明确："D003 没有说不允许上云，当时没有数据库，用户部分信息就存本地。"
  - 原版措辞过强（"v0.3 之前不上云""强烈反对上传儿童数据"），与真实意图不符。
  - 修订方向：**保留分层存储的工程事实**，但**去除"原则上云禁止"的态度**。
  - D011（听写拍照）已为"图片可走云"留出接口空间。
- 背景与冲突点（2026-09-10 首次讨论）：
  - 用户提出"是否需要数据库存单词信息和用户信息"。
  - 单词（共享内容）和用户（私有数据）性质完全不同，需要分层处理。
  - D002 已确立"MVP 维持 HTML 静态原型"原则，与"是否上数据库"直接相关。
  - 项目 00_总览第 5 条原则："先用简单方案验证真实效果，再扩展账号同步和 AI 能力"。
- 各角色观点摘要（2026-09-10）：
  - 产品负责人：v0.1 不上数据库；上数据库会立即引入 6 个新问题（后端/部署/账号/合规/团队/隐私），让"先验证教学法"失焦。
  - 资深英语教师：词库必须结构化、版本化、可审核，但不需要数据库；用 Git + JSON + 教师审核签字。
  - 学习科学专家：学习数据后期需要数据库（算法燃料），但 MVP 不必；v0.1 跑 2 周数据量小，Excel 可分析；要求数据可导出。
  - 初一学生代表：只关心"换设备还能不能用"；v0.1 至少给个二维码导入导出。
  - 家长代表：v0.1 阶段**默认**不上云（避免儿童数据合规风险），但**不绝对禁止**；如果未来提供家长可控的云同步开关，可接受。
  - 交互视觉设计师：v0.1 不用设计登录页，但要支持"本机档案切换"解决多孩问题。
  - 技术负责人：4 个理由不建议 v0.1 上数据库——成本/合规/延迟/可逆性，但**不构成永久禁用**。
- 最终决策：**分层存储，v0.1 不上数据库**
  1. **单词/词库** = 静态 JSON + Git + 教师审核，**永远不上数据库**（词库是教学法核心资产，不属于用户数据）。
  2. **用户私有数据** = v0.1 默认存 localStorage（不依赖数据库/云服务）。**未来可走云**，前提是：
     - a) 用户主动选择（家长配置里"开启云同步"开关，默认关闭）；
     - b) 数据归属家长可导出可删除（数据可移植权）；
     - c) 走 BaaS（Supabase/微信云开发/LeanCloud）而非自建后端，降低合规成本。
  3. **v0.1.5 增加"JSON 导入导出"**，作为云同步的备选。
  4. **v0.6+ 评估可选云同步**：账号 + 跨设备同步 + 错词云端聚合；触发条件 = 至少 3 家庭试用 5 天后明确要求"多设备无缝"。
  5. **图片类数据（听写照片 D011）**：默认存本机；如启用云同步，可一并上传（家长可控）。
  6. **OCR/AI 批改等需要上传图片/文本的功能**：必须**用户主动触发**（点"AI 复核"才上传），**默认不上传**；上传走家长选择的云服务商。
- 决策人/讨论来源：用户提问（2026-09-10） + 7 角色评审 + 用户 2026-09-11 修订
- 备选方案与放弃原因：
  - 放弃"v0.1 直接上数据库"：成本/合规/延迟/可逆性 4 重风险，且与"先验证教学法"原则冲突。
  - 放弃"完全用云端 BaaS（不落地 localStorage）"：v0.1 阶段数据库/账号不是必需，且增加合规风险。
  - 放弃"用 IndexedDB 替代 localStorage"：v0.1 数据量小（5-10MB 够用），IndexedDB 复杂度高，等 v0.2 真不够用再迁移。
  - 放弃"v0.1 做账号体系"：无服务器，账号无意义；做账号 = 强制上云 = 风险叠加。
- 决策后的影响：
  - **00_总览 新增原则第 6 条**：内容数据走 Git + 静态 JSON；用户数据 v0.1 走 localStorage；云同步是 v0.6+ 的**可选**能力。
  - **词库 JSON 增加字段**：`version` (semver)、`reviewed_by` (教师姓名)、`reviewed_at` (ISO8601)、`review_notes` (string)。
  - **用户数据 schema 设计**：`profile` (本机档案切换)、`words_state` (单词掌握度)、`dictation_log` (听写记录)、`settings` (家长配置)、`dictation_photos` (听写照片，默认存 localStorage)；统一提供 `export/import` JSON 接口。
  - **Backlog 调整**：
    - P0 新增："用户数据 localStorage 抽象层 + JSON 导出/导入"；
    - P1：账号/同步相关任务保持 P1（v0.6+ 评估）；
    - P2 新增："IndexedDB 迁移"（v0.2 评估）；
    - P3 候选："隐私合规流程（监护人同意 + 数据删除）"放到云同步功能启动前完成。
  - **OCR/AI 批改 v0.6 候选**：
    - 端侧 OCR（Tesseract.js / PaddleOCR）：零隐私风险，但模型大（5-15MB）、手写英文识别率 70-80%；
    - 云 OCR / LLM Vision：识别率高，但需图片上云 → **D011 现状（人工批改）保持默认**；
    - 用户主动触发的"AI 复核"（v0.6 候选）：家长配 API key / 选云服务商后才启用，默认不开启。
  - **UI 影响**：
    - 首次使用弹窗"数据存本机浏览器（家长可控）"；
    - 设置页增加"本机档案切换""导出/导入""每周备份提醒""云同步开关（v0.6+）"；
    - v0.1 不做登录页、注册页、找回密码页。
- 需要验证的假设：
  - H1：localStorage 容量（5-10MB）能否撑住 1 个孩子 1 学期 Unit 1-Unit 12 的错词本和学习记录（含听写照片后是否触顶）。
  - H2：v0.1 数据可导出后，家长是否愿意每周主动备份。
  - H3：多孩家庭本机档案切换是否够用，还是会要求账号体系。
  - H4（新增，2026-09-11）：家长对云同步的实际需求强度——如果 3 家庭试用 5 天后没人提"多设备同步"，云同步 v0.6 暂缓。
- 验收标准：
  1. v0.1 词库以单一 JSON 文件存放，Git 历史可追溯；每个版本有 `reviewed_by` / `reviewed_at` 字段。
  2. v0.1 用户数据默认存 localStorage，DevTools Network 面板在 v0.1 任何**默认**操作下**无外部请求**（OCR/AI 等高级功能需用户主动触发且默认关闭）。
  3. 提供"导出/导入"按钮，导出 JSON 文件在另一台设备/浏览器可恢复全部学习数据。
  4. 支持"本机档案切换"，≥ 2 个孩子的数据完全隔离。
  5. 首次使用显示"数据存本机"说明，含家长告知语。
  6. v0.2 评估 localStorage 容量是否触顶；v0.6+ 评估云同步触发条件。

  - 原："**v0.3 评估 Supabase BaaS**" → 改："v0.6+ 评估云同步（多选 BaaS），触发条件见 H4"
  - 新增：OCR/AI 批改走"用户主动触发"原则（D011 默认人工批改不变）
