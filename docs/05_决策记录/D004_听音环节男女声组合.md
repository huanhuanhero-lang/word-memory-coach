# D004｜听音环节改为"男声 + 女声"组合播放

- 日期：2026-09-10
- 议题：听音环节点击"听"按钮后，是否改为男生读一次 + 女生读一次
- 背景与冲突点：
  - 用户提议：听两次，模仿英语老师带读（男老师 + 女老师）。
  - 这是经典口语教学法，但 TTS 在不同浏览器 voices 数量差异巨大（Chrome 桌面 5-10 个 / iOS Safari 经常只有 1 个）。
  - 听音环节属于"建立基线音感"阶段，差异化朗读是研究支持的"auditory distinctiveness effect"。
- 各角色观点摘要：
  - 产品负责人：支持作为听音环节默认播放模式；保留"只听男/女"备选。
  - 资深英语教师：经典教学法，赞同；pitch 范围 [0.85, 1.15] 安全，中间停顿 600-800ms。
  - 学习科学专家：强烈支持声纹差异化对低龄段工作记忆编码的增益；不能只听一遍，要确保跟读环节再听。
  - 初一学生代表：喜欢"像英语课"的感觉；要求男女声切换不能太快。
  - 家长代表：赞同但要求 fallback；家里设备可能只有 1 个 voice。
  - 交互视觉设计师：主按钮 + 灰色备选；只改听音环节（步骤 1），其他环节保持女声。
  - 技术负责人：必须做 voices 探测 + fallback；pitch 安全范围 [0.7, 1.3]；两次 speak 用 onend 串联。
- 最终决策：**听音环节改为男声 + 女声组合播放，作为 v0.3.1 体验优化**。
- 决策人/讨论来源：用户提议 + 7 角色评审（资深英语教师 + 学习科学专家 + 技术负责人共同主导）
- 备选方案与放弃原因：
  - 放弃"同声两遍"：违背用户原意，也错过声纹差异化教学法价值。
  - 放弃"在所有环节都改男女声"：跟读、合成、听写环节 UI 设计师建议维持女声。
  - 放弃"pitch 调到 0.6/1.4 极端值"：会失真像卡通人物，孩子反感。
- 决策后的影响：
  - `TTS.playWordDual(word, onComplete)` 新增 API。
  - `TTS.init()` 增加 voices 性别探测（按 voice.name 关键词匹配）。
  - 听音页（步骤 1）主按钮改名为"🔊 听（👨 → 👩）"，保留"只听男生/只听女生"小字按钮。
  - 家长配置页（`#settings`）新增"听音播放模式"选项：男女各一次 / 女声两次 / 男声两次。
  - iOS Safari fallback：检测无第二 voice → 用同声 + pitch 1.2 + UI 提示"已用高低音模拟"。
- 需要验证的假设：
  - H1：iOS Safari 上"用 pitch 1.2 模拟女声"是否足够清晰区分。
  - H2：男女声组合对初一学生的音感建立是否真有数据支撑（拟在 v0.2 试用 5 天后回访）。
- 验收标准：
  1. Chrome / Edge / Android 浏览器：男女声可清晰区分。
  2. iOS Safari：检测到无第二英文 voice 时自动 fallback 到同声 pitch 1.2，并在 UI 显示提示。
  3. 男→女间隔 ≥ 600ms，让孩子有时间跟读。
  4. 主按钮文案明确"👨 → 👩"图标。
  5. 全程无 console 错误。
  6. 3 设备类型（Chrome 桌面 / Safari iOS / 微信内置浏览器）零失败。
