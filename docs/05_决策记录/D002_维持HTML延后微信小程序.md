# D002｜MVP 技术路线维持 HTML，微信小程序延后到 v0.3

- 日期：2026-09-10
- 议题：是否在 MVP 第一版直接以微信小程序作为产品形态
- 背景与冲突点：
  - 用户提出"做成微信小程序方便使用"——初一学生和家长的真实诉求。
  - 但项目 00_总览第 5 条原则明确："先用简单方案验证真实效果，再扩展"。
  - HTML 原型 vs 微信小程序，工具链、审核、API 能力差异巨大。
- 各角色观点摘要：
  - 产品负责人：先不替换，做双轨；HTML 验证效果，效果验证通过后再迁移。
  - 资深英语教师：技术中立；提醒 TTS 在小程序里需用预录音频或同声传译插件。
  - 学习科学专家：技术中立；提醒小程序有"反正已经拿到手机"的双刃剑效应。
  - 初一学生代表：**强烈想要小程序**；建议名字低调（"单词教练"）避免同学侧目。
  - 家长代表：支持小程序；担心孩子借口用手机，需要"每天 15 分钟"硬上限。
  - 交互视觉设计师：rpx / 安全区 / 胶囊按钮都要重新适配，UI 工作量≈重做一遍；词库和内容设计可复用。
  - 技术负责人：MVP 阶段强烈建议先 HTML；TTS/账号/审核三大障碍在小程序里都要重做。
- 最终决策：**MVP 第一版维持 HTML 原型**；词库 JSON 必须平台无关；效果验证后迁移微信小程序。
- 决策人/讨论来源：用户提议 + 7 角色评审（技术负责人 + 产品负责人共同主导）
- 备选方案与放弃原因：
  - 放弃"MVP 直接做小程序"：审核/账号/TTS 三大障碍延长验证周期 2-4 周，违背"先验证再扩展"原则。
  - 放弃"完全放弃 HTML"：失去快速迭代和零门槛体验。
  - 放弃"双线并行"：MVP 阶段资源不足以同时维护两套 UI。
- 决策后的影响：
  - Backlog 中"账号与跨设备同步"维持 P2；但"微信小程序迁移"从无提升为 P1。
  - 词库 JSON 平台无关约束：不引用 localStorage、不绑定 HTML 标签；预留 `audio_url`、`example_audio_url` 字段。
  - TTS 在 v0.1 仍用浏览器原生；迁移小程序时再切预录音频 + 同声传译。
  - 文档新增迁移评估节点：v0.2 发布 2 周后，基于"主动使用率"和"错词率下降"两个数据决定是否启动小程序开发。
- 需要验证的假设：MVP HTML 版能否在 4 周内拿到"孩子愿意主动用"和"错词率下降"两个数据。
- 验收标准：
  1. v0.2 发布后 2 周内，有 ≥ 3 个家庭连续使用 5 天以上。
  2. Unit 1 词库 v0.2 版本可在 HTML 和小程序两端解析同一份 JSON（无平台相关字段泄漏）。
  3. 学习记录新增字段 `used_channel`（记录本次学习是 HTML 还是小程序），为迁移决策提供数据。
