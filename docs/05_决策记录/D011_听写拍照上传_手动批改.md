# D011｜听写拍照上传 + 手动批改（v0.5 范围）

- 日期：2026-09-11
- 议题：听写结果怎么收集？纯字母输入还是拍照上传？
- 背景与冲突点：
  - 用户洞察：**听写时学生在作业本写，拍照上传保存听写结果**——比纯字母输入更符合初一作业习惯。
  - 当前听写流程：进入 `/dictation/:id` → TTS 朗读单词 → 屏幕"写完了"按钮 → 跳转回首页。结果**未留存**。
  - 真实痛点：家长/学生需要**复盘**听写过程（哪些写对、哪些写错、错在哪儿），但当前没有存档。
  - D003 隐私约束：数据存本机，不上云。
- 各角色观点摘要：
  - 产品负责人：**强烈同意拍照**。这是真实场景的核心环节。
  - 资深英语教师：**手动批改**——家长/学生看照片勾对错，不靠 AI。
  - 学习科学专家：拍照留档 = 元认知训练（metacognition），学生回顾自己的错误比单看对错列表更有效。
  - 初一学生代表：拍照简单，比起在屏幕上一个字母一个字母敲更真实。
  - 家长代表：照片可以发朋友圈打卡（社交动机）。
  - UI 设计师：拍照按钮显眼，操作 ≤ 2 步。
  - 技术负责人：浏览器 `<input type="file" accept="image/*" capture="environment">`；图片压缩后 Base64 存 localStorage（5MB 容量上限，够 10 张）。
- 最终决策（**v0.5 范围**）：
  - 听写流程结束前，按钮"📷 拍照上传作业本"
  - 移动端：自动调起后置摄像头（`capture="environment"`）
  - 桌面端：弹出文件选择器
  - 图片压缩到 ≤ 200KB 存到 localStorage
  - 批改流程：拍照 → 逐词勾选 ✓/✗ → 入错词本 → 错词本每条可"查看作业本照片"
  - 降级：用户拒绝授权摄像头 / 桌面无摄像头 → 跳过拍照，仍可手动批改
- 决策人/讨论来源：用户 2026-09-11 洞察 + 7 角色评审
- 备选方案与放弃原因：
  - 放弃「AI 自动批改（LLM/Vision）」：D003 隐私风险 + v0.5 范围控制。
  - 放弃「屏幕内字母拼写」：已评估，体验差，与"作业本听写"真实场景脱节。
  - 放弃「纯本地 OCR（tesseract.js）」：模型大（10MB+），localStorage 装不下；v0.6 评估。
- 决策后的影响：
  - `app.js` 新增 `renderDictationBatch()` 批量听写页（N 词 TTS 连读）
  - `app.js` 新增 `stepDictationPhotoUpload()` 拍照上传步骤
  - `app.js` 新增 `stepDictationGrade()` 手动批改（逐词勾选 ✓/✗）
  - `storage.js` 加 `dictation_photos: [{ word_ids, data_url, taken_at, grades }]`
  - 错词本加"📷 查看作业本"入口
- 验收标准（v0.5）：
  1. 听写 N 词后，可拍照 1 张上传（移动端调起摄像头，桌面端选文件）
  2. 5 张照片内 localStorage 不超 1MB
  3. 拍照后逐词勾选 ✓/✗ → 错词入错词本
  4. 错词本每条错词可"查看作业本照片"
  5. 拒绝授权 / 桌面无摄像头 → 降级为"跳过拍照，继续手动批改"
- 暂不实现（v0.6 评估）：
  - AI 批改（LLM/Vision）
  - 本地 OCR（tesseract.js）
  - 多张连拍（一次拍 5 词）
- 版本：v0.5（D011 当前 v0.4.x 不实现，列入 v0.5 待办）
