# D012｜听写前跟读：把"音→嘴"和"音→手"绑死

- 日期：2026-09-11
- 议题：听写前是否要再跟读一次？
- 背景与冲突点：
  - 用户洞察：**听写前让学生先跟读，再听写**——"音→嘴"和"音→手"绑死一起，再默写。
  - 当前 8 步流程在第 7 步"主动回忆"完成后直接进入第 8 步"听写门控"，中间无跟读过渡。
  - 真实课堂：老师听写前会"再读一遍"，学生跟读，然后再听写。
  - 学习科学：多通道编码（multimodal encoding）= 听 + 读 + 写三通道同时加工 = 强记忆。
- 各角色观点摘要：
  - 产品负责人：**同意**。简单一步，效果好。
  - 资深英语教师：好建议，真实课堂就是这样。
  - 学习科学专家：多通道编码 = 深度加工，符合 Paivio 双编码理论。
  - 初一学生代表：跟读简单，不费脑。
  - 家长代表：跟读是免费的练习。
  - UI 设计师：在第 7 步和第 8 步之间插 1 步，UI 简洁。
  - 技术负责人：复用 `TTS.speak` + `playRepeat`，改动极小。
- 最终决策：
  - **新增第 8 步"听写前跟读"**（在原第 7 步"主动回忆"和原第 8 步"听写门控"之间）
  - 流程：TTS 慢速朗读（rate 0.6）→ 屏幕提示"🎤 跟读一次"→ 3 秒倒计时跟读 → 自动进入听写门控
  - 跟读次数：默认 1 次（设置页可调 1-3 次，与 D005 遍数配置一致）
- 决策人/讨论来源：用户 2026-09-11 洞察 + 7 角色评审
- 备选方案与放弃原因：
  - 放弃「听写时跟读」：听写时学生已经在写，嘴不动。
  - 放弃「跟读 3 次」：听写前已经做过跟读（第 2 步），1 次足够。
  - 放弃「不做这一步」：缺了这个桥梁，听写时学生容易"听不准 → 写错"。
- 决策后的影响：
  - `app.js` 新增 `stepPreDictationFollow(root, word)` 函数
  - `renderCard` 步骤数组加第 8 步
  - `storage.js` settings 加 `pre_dictation_follow_count`（默认 1）
- 验收标准（v0.4.x）：
  1. 单词学完 7 步后，进入"听写前跟读"页面
  2. 页面 TTS 慢速朗读 + 3 秒跟读倒计时
  3. 跟读完成后自动进入听写门控
  4. 设置页可调跟读次数（1-3）
- 版本：v0.4.x
